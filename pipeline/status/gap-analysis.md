# 残課題の対応(2026-09-04 後半)

`pnpm --filter api test` **263/263** · `pnpm --filter @rpgllm/llm test` **135** · `pnpm e2e` **47 passed / 4 skipped / 0 failed** · 全 typecheck 緑。

## 1. Batch ティア — **解消**(設計上唯一の未達だった項目)

Message Batches API 経路を実装し、結果は `custom_id` で突き合わせる(順序では対応付けない)。待たされる人がいない生成(雑談 G2 / 記憶統合 G7 / 不在ダイジェスト G10 / 審査 GJ)をここに載せ、**スケジューラが呼ぶのはバッチ版**にした。即時性が要る `GET /v1/digest` と `GET /v1/memory/:id` は対話版のまま(バッチは 24 時間 SLA)。

実測(クリーンな DB で雑談補充ジョブを実行):

| レーン | 呼び出し | コスト | 生成数 |
|---|---|---|---|
| batched | 5 | $0.013905 | 52 投稿 |
| interactive | 3 | $0.055853 | 12 投稿 |

定価 $0.027808 → 請求 $0.013905、**実現割引 50.0%**(期待値どおり)。

副産物: G2 / G10 / GJ はこれまで G1 の合成プロンプトで代用されていたが本物の生成器になり、審査員が指定どおり Opus 5 で動くようになった(それまで黙って Sonnet に落ちていた)。

## 2. Thompson sampling — **解消**

固定 50/50 をやめ、Beta 事後分布による割当に。報酬は `quality − 0.4 × (cost / champion cost)` を 0..1 にクランプ。👍=1、👎/再生成/フォールバック=0、未評価=0.6(未評価を 0 にすると沈黙が失敗に見える)。割当はユーザー単位で固定(エンゲージメント指標が混ざらないため)、探索の下限あり。ガードレール違反で腕を自動停止、昇格には**呼び出し数・確信度・オフライン評価の 3 つ**が揃うことを要求し、`PromotionEvent` に根拠を残す。再生成呼び出しとバッチ行は集計から除外している。

## 3. オフライン評価 — **解消**

生成器ごとに 50 件の凍結セット(うち 15 件は手書きの難問: 流出ドラマ、失恋、日本語敬語、罵倒入力、境界的な自傷ケース、英日)。機械判定 40% + 審査員 60% で採点し、`EVAL_GATE` で昇格可否を決める。CLI は `node scripts/eval.mjs --generator G1`。

## 4. スケジューラ — **解消**

`pnpm --filter api worker` が 7 ジョブを cron で実行。**ジョブ名ごとに Postgres の助言ロック**を取るので、ワーカー二重起動や再デプロイの重なりで二重実行にならない。実行記録は `JobRun` に残り `GET /v1/jobs` で読める。失敗してもループは生き、SIGTERM で実行中を待って終了。

## 5. 認証コードの永続化 — **解消**

プロセス内 Map から Postgres へ。**API を複数インスタンスで動かせるようになった**。ソルト付きハッシュのみ保存、10 分、5 回、使い捨て、定数時間比較、1 アドレス 1 有効コード。

## 6. 連続ログインのカラム化 — **解消**

台帳からの導出をやめ `User.streakDays` 等を正本に。既存記録は初回読み出し時に移行。エネルギー上限のキャップは維持。

## 7. 課金 — **解消**(ただし実ストア未接続)

RevenueCat の Webhook が署名検証つきで本物に。イベント適用は一意なイベント ID を含む単一トランザクションで冪等。**返金は即時剥奪、キャンセル/期限切れは期間終了まで、決済リトライは猶予期限まで**。権利判定を 1 関数に集約し、エネルギー上限と広告可否がそこを経由する。復元はクライアントの申告 ID を信用せず、サーバが知る ID のみで照合する。

## 8. プッシュ配信 — **解消**(ただし認証情報未設定)

権限要求は**最初の投稿成功後**(起動直後に求めるのが拒否率を上げる最大の原因)。100 件ずつ送信、無効トークンを削除、23-8 時は送らない、日次上限あり。受領確認は非同期に埋まるため専用ジョブが 20 分ごとに後追いする。

## 9. テスト分離 — **解消**

実行ごとに専用 DB を作って捨てる。Web サーバが node を直接起動するようになり、SIGTERM が握り潰されてポートに API が残る問題も解消。

# 第4次: 世界そのものが足りない(2026-09-05)

前の3次はすべて「既にある世界を、どう良く見せ、どう安く回し、どう課金するか」の話だった。
そこを詰めきった結果、いちばん大きな穴が残っていることが見えた — **世界が3つしかない**。

## 10. ワールド生成 — **解消**

`05-ai-features.md` は「AIF-014 (G9) 実装済み」と書いていたが、これは誤記だった。
`packages/llm/src/generators/` に g9 は無く、3つの世界は手書きの TypeScript で、
新しい世界を足すには人間がバイブルを2ロケール分書くしかなかった。teardown で見た Status の
「13M ワールド」に対して、こちらは 3。桁が違うのではなく、種類が違う。

G9 を5段階に分けて実装した(concept/bible は high、cards/events は mid、texture は light)。
1 ワールド 14 呼び出し、**約 $0.32**。段階3〜5 は 4,389 トークンの共通接頭辞を共有するので、
11 呼び出しのうち 10 はキャッシュ読み出しになる(Haiku 4.5 の 4,096 下限を意識した設計)。
replay では API キー無しで全 8 ジャンル・2 ロケールが 4,400〜4,900 トークンのバイブルを出す。

## 11. ユーザー作成ワールド(AIF-003)— **解消**

B(チームが生成器で世界を量産する)だけでは、Status の「13M ワールド」には永久に届かない。
A(プレイヤー自身が作る)の動線も同時に作った。1 行 + ジャンル → 120 ジェム → 生成ジョブ → 完成。

安全性は 2 段構え。プレミスはシステムプロンプトの一部になるので、**生成前に**落とす
(ジェムもトークンも消費しない)。生成物は**公開前に**もう一度 G8 にかけ、`public` は必ず人間の
審査を通す。`private` は即座に遊べて、どの一覧にも出ない。`unlisted` はリンクで遊べるが発見されない。

### プレミス審査で難しかったところ

「高校生」「student」「trainee」は 8 ジャンル中 2 つの**普通の語彙**なので、単語一致では使えない。
組み合わせ規則にした: 未成年マーカー + 性的語 → ブロック、強い未成年マーカー(明示的な 18 歳未満、
「小学生」)+ 恋愛語 → ブロック。同様に「how to make X」も、名詞ではなく**形**で判定する — 覚醒剤を
題材にした犯罪ドラマは作れるが、作り方は聞けない。過剰ブロックを防ぐ許可側のテスト表を必ず添えている。

## 12. ジェムの入手経路が無かった — **解消**

ジェムはスキーマにもウォレットにも台帳にもあったが、**入る経路が連続ログイン報酬だけ**だった
(週 35)。120 ジェムのワールドは 3.5 週間かかる計算で、実質誰も studio に到達しない。
ウォレット作成時に 120(初日に 1 個だけ作れる)と、消耗型のジェムパック 3 種を足した。
課金側は非サブスクの購入を記録だけして**何も付与していなかった**ので、そこも塞いだ。

評価して算出 — gtm.md の $0.32 に**独立した方向から**着地し、あの数字に初めて裏が取れた。

3 つの問いのうち、**日本語の問いに対する最強の判定は「NEEDS A HUMAN」**。CJK 比率もエコー検査も

# 第9次 — リンクが、貼られた先で何になるか

## 32. 共有リンクが展開されない — **解消**

リールを作った理由は流通で、流通は**他人のフィードの中**で起きる。そこでは1リクエストで
「カードになるか、青いURLのままか」が決まり、そのリクエストはアプリのJavaScriptを実行しない。
Expo の web エクスポートは単一ページのバンドルなので、クローラが `/world/:id` を取りに行くと
**空の `<div id="root">`** が返る。つまりこれまで送られた共有リンクは全部、タイトルも説明も画像も無い
裸のURLとして表示されていた。**リールという配布物を作っておいて、配布面が壊れていた。**

移した先は API。`/s/w/:id` / `/s/m/:slug` / `/s/c/:handle` が `og:`/`twitter:` 付きの本物の HTML を返す。

**見せるものは、既に公開されているものだけ。** ワールドは `published` かつ `public`/`unlisted` ——
棚と同じ述語なので、通報で下ろされた世界（`review` + `pulledAt`）はその瞬間に展開されなくなる。
`unlisted` は展開されるが `noindex`：**リンクが配布であって、検索結果は避けた棚のほう**だから。
削除済みアカウントの作者ページは404（クレジット行はDB上30日生き残るが、ページ上で生き残ってはいけない）。

**リダイレクトはしない。** UA を見て人だけアプリへ飛ばすのは、新しいクローラが出た日に壊れるうえに
クローキングそのもの。全員に同じページを返し、人には大きな「開く」を1つ出す。**受け取った人には1タップ増える**
—— 意図した代償で、E2E-045 がその1タップが本当にワールドに着地することを固定している。

## 33. og:image を、依存を増やさずに作った — **解消、ただし文字は無い**

この製品の絵は全部クライアント側の SVG（`WorldCard.tsx`）で、**主要なアンファーラは SVG を描かない**
（X も Facebook も）。ヘッドレスブラウザや画像ライブラリを足す選択肢もあるが、**Chromium が要る og:image は
Chromium が落ちた日に落ちる og:image**。なので `node:zlib` だけで PNG を書いた
（真色8bit、行フィルタは `Up` —— 縦グラデーションなら上の行との差はほぼゼロなので、197KB に収まる）。

構図・パレット・PRNG・種はすべて `WorldCover` と同一。**アプリで見る表紙と、Xで見るカードが同じ絵**になる。
違う絵を出すプレビューは、押した全員に小さな嘘をついている。

**文字は描いていない。** フォントが無く、ラスタライズは小さな仕事ではない（`ja` は 3MB の CJK フェイスと
シェーパーが要る）。言葉は `og:title` / `og:description` が運び、主要プラットフォームは全部それを画像の
横に描く。**それでも、見出しが焼き込まれたカードのほうが強い。** これは回避策ではなく、
「フォントを積む」という未着手の仕事である。

描画は約100msのCPUなので、両ポスター経路とも**行を引いてから描く**。存在しない種を無限に描かせられる
公開エンドポイントは、匿名の1本の接続でプロセスを落とせる。

## 34. 実装中に見つかったもの

- **`atHandle()` は `@` を付けない。** API 契約はハンドルを裸で返し、`@` はクライアントが描く。
  共有ページは**この面のクライアント**なので自分で描く必要があり、最初の実装は「by rina」を
  リンクプレビューに出荷しかけた。テストで捕まえた。
- **`EXPO_PUBLIC_APP_URL` が丸ごと不要になった。** 共有リンクがアプリ自身の origin を指す必要が消えたので、
  クライアントは「web アプリがどこにあるか」を知らなくてよくなった。知る必要があるのは API 側だけ
  （`PUBLIC_APP_URL`、「開く」の行き先）。死んだ変数は消した。
- **モーメントのポスターは、ワールドのポスターではいけなかった。** 最初の実装はモーメントのカードの
  `og:image` を `/s/w/:slug/poster.png` に向けていた。モーメントは公開だが、それが起きたワールドは
  たいてい非公開（特に初期）——つまり**実際の共有のほとんどで `og:image` が404を返し、その周りの
  ページは完璧に見える**。ゲートを掛ける行はモーメント自身でなければならないので、
  `/s/m/:slug/poster.png` を別に生やした（絵の種はワールドのままなので、カードとリールとワールドは
  同じ1枚の絵を持つ）。
- **製品に名前が無い。** `og:site_name` に入れる語が `packages/shared` に無く、`app.json` は
  "status-clone"。`PUBLIC_APP_NAME` を env に置いて既定を `RPGLLM` にしたが、これは**赤の他人が
  最初に読む語**であって、リンクプレビューはそれが我々の問題ではなく他人の問題になる最初の面である。

## 35. サインインコードの配信手段が無かった — **解消**（最大の発射阻害要因）

`ConsoleMailSender` がコードをサーバーログに出力し、`setMailSender()` は**一度も呼ばれていなかった**。
これは 2 つの問題が 1 枚のコートを着ている状態：**チーム外の誰もサインインできず**、かつ
システムが発行する全資格情報が平文でログに残り、10 分の TTL より長く生き続ける。
しかも**全ユーザーが最初に必ず通る唯一の経路**である。

`services/mail.ts`：Resend / Postmark への JSON POST 1 発、**依存追加ゼロ**（認証経路に SDK の
推移的依存ツリーを持ち込まないため）。決めたこと 3 つ：

- **送れなかった送信は送信ではない。** `{sent:true}` と答えて空の受信箱を見つめさせるくらいなら
  502 を返す。プロバイダのステータスはログに 1 行、**コードは絶対に書かない**。
- **マジックリンクにしない。** リンクは転送 1 回で他人のセッションになる。6 桁は開いているアプリに
  打ち込むもので、メールクライアントから誤クリックできない。
- **5xx は 1 回だけ再試行、4xx はしない。** 送信元未検証は一過性の失敗ではなく、
  再試行はスピナーを見つめる時間を倍にするだけ。

戻ってきたプレイヤーには日本語で届く（アドレスから `User.locale` を引く。初回は `en`）。

## 36. 起動ゲートが「悪用可能」しか見ていなかった — **解消**

4 つのチェック（JWT / TEST_HOOKS / BILLING / ADS）を全部通しても、**製品として壊れたまま起動できた**：

| 通っていた設定 | 本番で起きること |
|---|---|
| `LLM_MODE=replay` | 課金ユーザー全員に同じ 3 つの定型返信を配る |
| `ANTHROPIC_API_KEY` 無し | 全生成がフォールバック |
| `CORS_ORIGINS=*` | 任意のオリジンが認証済み JSON を読める |
| `ADMIN_TOKEN` 無し | **誰も審査できない** = 公開ワールドが 1 本も棚に並ばない |
| `PUBLIC_APP_URL` 無し | 全招待・全共有リンクが、我々が所有していない `rpgllm.example` を指す |

## 37. 広告報酬のリプレイ — **解消**

署名検証は「このコールバックは本物か」に答えるが、「**これを見るのは 4 回目ではないか**」には答えない。
`transaction_id` は取り出された後、捨てられていた。自分の端末で 1 本正規のコールバックを取れば、
同じ URL を投げ続けて日次上限までエネルギーを鋳造でき、それを毎日できた。

`AdRedemption` の一意制約が唯一の防壁で、**付与と同じトランザクション**で書く（read-then-write なら
同時リプレイ 2 本が両方通る）。取引 ID を持たない検証済みコールバックは、
重複排除できない報酬はリプレイできる報酬なので、**拒否**する。

ついでに鍵セットの取得も実装した（従来は恒久的に fail-closed = 広告報酬が無言で機能停止）。
更新契機はタイマーではなく**キャッシュミス**（ローテーションは「知らない key_id」としてしか観測できない）、
下限間隔付き（未知 ID を外向きリクエスト増幅器にされないため）、失敗時は**直前の good copy を保持**
（Google の瞬断で製品の全広告報酬が止まる方が悪い失敗）。

## 38. 1 日の費用に天井が無かった — **解消**

この製品の制限は全部**ユーザー**を縛るもので（1 日 10 エネルギー、広告 5 回、ワールド 3 本、
毎分レート制限）、**請求書**を縛るものは 1 つも無かった。止まらない再試行ループ、高いアームを
昇格させたバンディット、スタジオを自動化する 1 アカウント、バイブルが育って出力が 8k になったプロンプト
— どれも**まだ書いていないバグ**であり、それに対する防御は注意力ではなく上限である。

`withBudget` が**ゲートウェイを Proxy で包む**（列挙ではなく Proxy なのは、
許可リストの失敗様式が「最新で最も高価なジェネレータが登録漏れ」だから。この interface は
このプロジェクト中に 3 回増えた）。API とワーカーの両方で包む — ジョブは**誰も見ていない側**で、
オフラインディレクタは不在プレイヤー全員を 1 回で処理する。

- **実際の金だけ数える**（`live` のときだけ発動）。想像上の予算切れで本物の障害を起こさない。
- **枯渇は障害と同じ見え方**：throw する。それは `LLM_MODE=fail` そのもので、全呼び出し側が既に
  扱えるパスであり、スイートが叩いている。プレイヤーはフォールバック返信とエネルギー返却を受け取る。
- **カウンタではなく `GenerationLog` から読む**。請求書と突き合わせる行そのもの。別カウンタは
  ずれる第二の真実で、しかも**何かがおかしい時に限って下振れする**。数秒キャッシュし、各呼び出しが
  自分のコストを足し込むので、超過は「1 リクエスト分」ではなく「1 更新窓分」で頭打ちになる。
- **`unlimited` は打ち込ませる。** 上限なしは正当な答えだが、それは**答え**であって、
  空欄は「その数字は必要だった」と後で気づく方法である。

`GET /v1/cost/live` に `budget` を載せた（障害時に見るのはこの面で、`exhausted: true` が
「なぜ全員が急にフォールバックを受け取っているのか」への回答になる）。

## 39. モデレーション決定が誰のものか分からなかった — **解消**

管理面のゲートは**共有シークレット 1 本**、審査者名は**クライアントが自分で書くヘッダ**だった。
片方だけでも問題で、両方あると：ゲートを通れる者は誰の名義でも決定を書けるし、
1 人辞めるたびに全員のトークンを回す必要がある（＝回されない）。
SLA と取り下げ判断を持つキューの監査証跡としては成立していない。

`ADMIN_TOKENS=rina:secret1,koji:secret2`。名前は**マッチしたシークレット**から来るので、
`x-reviewer` ヘッダは無視される。共有 `ADMIN_TOKEN` のままの環境は名指しできる人が居ないので、
決定を `shared:<ラベル>` として記録する — **grep できる正直さ**。審査者に名前を付けられないキューは
そう見えるべきで、ゲートを通れば誰でも打てた名前の列を持つべきではない。

比較は全件走査（早期 return はリストの何番目にシークレットがあるかを時間で漏らす）。
ついでに `adminTokenMatches` の `===` を定数時間比較にした。

## 40. 実行時 DDL の返済 — **解消**

`JobRun` / `PushTicket` はモデルとマイグレーションが既に存在していたのに、コードは

**既に古かった**（`recordPushTickets` は実装済み）。ドキュメントの嘘は、コードの嘘より長生きする。
