# Gap Analysis — MVP 実装後の欠落監査

- date: 2026-09-04 / 監査対象: E2E P0 16/16 緑時点のコード(`84464c9`)
- 方法: 実コード読解。仕様(`spec/`)との差分ではなく、**「本番に出して壊れる/出せない」観点**での監査。
- 重要度: **S0 = セキュリティ(即座に悪用可能)** / **S1 = ストア審査ブロッカー** / **S2 = プロダクト差別化の未達** / **S3 = 運用品質**

---

## S0 — セキュリティ(本番投入不可)

| # | 欠落 | 場所 | 影響 |
|---|---|---|---|
| S0-1 | **認証バイパス**: 固定コード `000000` が全メールで常に通る | `routes/auth.ts` | 任意アカウントへのなりすまし。実質認証なし |
| S0-2 | **JWT_SECRET の既知デフォルト値**で起動できる | `env.ts` | トークン偽造 |
| S0-3 | **`.env.example` を実行時フォールバックとして読む** | `index.ts` | 本番で開発用シークレットが有効化される |
| S0-4 | **レート制限が皆無** | 全ルート | 投稿=LLM課金なので**財布が直接の攻撃対象**。認証・広告報酬も無制限 |
| S0-5 | **CORS `origin:"*"`** を認証付き API に適用 | `app.ts` | 任意サイトから認証付きリクエスト |
| S0-6 | **広告報酬トークンが固定文字列** | `routes/wallet.ts` | エネルギー無限取得 |
| S0-7 | **`?token=` を全ルートで受理** | `auth.ts` | アクセスログ/リファラ経由のトークン漏洩 |

## S1 — ストア審査ブロッカー(プロダクト)

| # | 欠落 | 根拠 |
|---|---|---|
| S1-1 | **アカウント削除がない** | App Store Guideline 5.1.1(v)。アカウント作成機能があるアプリは**アプリ内削除が必須** |
| S1-2 | **通報・ブロックがない** | Guideline 1.2(UGC)。AI 生成物でも、13+ でキャラが絡む以上必須。**審査で確実に落ちる** |
| S1-3 | **利用規約/プライバシーポリシーの導線がない** | EULA 表示義務、GDPR/APPI |
| S1-4 | **設定画面が存在しない**(SCR-033 が MVP から脱落) | サブスク管理・言語切替・ログアウト・法務リンクの置き場所がない |
| S1-5 | **購入復元が未実装**(TODO のまま) | Guideline 3.1.1 必須 |
| S1-6 | **未成年の広告設定はあるが、データ収集の同意 UI がない** | EU DSA / 英 AADC |

## S2 — プロダクト差別化の未達(teardown で「Status を上回る」と定義した項目)

| # | 欠落 | teardown での位置づけ |
|---|---|---|
| S2-1 | **Offline World Director (AIF-001)** | 最大の差別化。不在中も世界が進み、復帰時にダイジェスト。**未実装** |
| S2-2 | **プッシュ通知** | リテンションの主要手段。**基盤ごと無し** |
| S2-3 | **Relationship Memory Ledger (AIF-002)** | 「キャラが覚えている」ことの可視化。**UI 無し**。加えて **G7(記憶統合)が一度も呼ばれない**ため MemoryEntry が無限に溜まる |
| S2-4 | **Shareable Moment (AIF-005)** | Status の成長エンジンは手動スクショ。自動カード生成で K ファクターを上げる計画が未着手 |
| S2-5 | **リファラル** | 招待でエネルギー。無し |
| S2-6 | **プロフィール画面 (SCR-026)** | 自分のスタッツ・レベル・投稿履歴が見られない。進行の実感が薄い |
| S2-7 | **G2(雑談プール補充)が呼ばれない** | シード時の在庫を消費するだけ。長期プレイで枯れる |

## 対応方針

S0 と S1 は**リリース前提条件**なので全件埋める。S2 は「Status を上回る」ための本体なので、リテンションに直結する S2-1/2/3/6 と成長の S2-4/5 を実装する。S3 は S3-5(コスト可視化)を最優先、次に CI/デプロイ。

実施記録は `build-notes.md` の各エージェント節に残す。
