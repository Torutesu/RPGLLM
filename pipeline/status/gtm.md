# 勝ち筋 — Status に対して、どこで勝てて、どこでは勝てないか

teardown の実測値と、こちらの実測コストを突き合わせた戦略メモ。
数字の出典は `teardown.md` と `cost-architecture.md`、こちらの計測値は本リポジトリの実行結果。

---

## 0. 最初に、勝ち筋ではないものを潰す

**コストは差別化にならない。** ここは正直に書く。

Status は初期 Claude 3.5 Sonnet で $12〜15/ユーザー/日を払い、Inworld でタスク分解+ルーティングして
**95% 削減**、数セント/日に着地した。こちらの実測は **$0.0057〜0.0082/アクション**、キャッシュヒット率
88〜90%、Batch ティアの実測割引 50.0%。1 日 10 アクションで **約 $0.07/日**。

つまり **同じ桁**。「うちは安い」は成り立たない。Status はもう安い。

こちらにあるのは水準ではなく**構造**の優位で、それは launch の武器ではなく耐久力の話：

- 生成器を 5〜10 個に割ってあるので、どこを安くするかを個別に選べる
- Thompson sampling のバンディットが `品質 − 0.4 × コスト比` で報酬を定義しているので、
  安くすると品質が落ちる場合は自動で戻る
- オフライン評価ゲートがあるので、昇格前に品質を測る

Status は 2025 年に**素朴に安いモデルへ寄せてエンゲージメントを 78% 失っている**。
こちらの装備はその事故を繰り返さないためのものであって、「もっと安い」ためのものではない。
**launch の売り文句にしてはいけない。**

**19 日で 100 万ユーザーは、プロダクトの結果ではない。** β期に Discord/TikTok で 10 万 DL、
前作 Kiwi で 200 万 DL、NYC 6 人、$17M。こちらの流通はゼロ。
プロダクト同等 ≠ 流通同等。ここを混同した瞬間に計画は嘘になる。

## 1. 本当の勝ち筋は 3 つ

### 勝ち筋 A: 世界に「作者」を持たせる

Status のワールドは 1,300 万ある。だがそれは**生成された**ワールドであって、
**書かれて共有された**ワールドではない。作者がいない。プレイ数もフォロワーも付かない。
つまり **13M は虚栄の数字**で、意味のある数字は「N 回以上遊ばれたワールドの数」。

こちらは A 動線（プレイヤーが 1 行から世界を作り、公開し、他人に遊ばれる）を作った。
ここが効くと、Status に構造的に無いループが回る：

```
世界を作る → 遊ばれる → プレイ数が付く → 作者として認知される → もっと作る
                ↓
        遊ぶ側にとっては「無限の新作」
```

コンテンツが AI 生成なので UGC の冷スタート問題が無い、というのが Status の強さだった。
**作者を足しても冷スタート問題は起きない**（プリセット 3 本 + チーム生成の量産で床が保証されている）のに、
上限だけが外れる。これが唯一の**複利が効く**差分。

ただし条件がある。**プレイ数が可視化され、作者にクレジットが返り、良い世界が発見される**こと。
その 3 つが無い UGC は「投稿できるだけ」で誰も作らない。

### 勝ち筋 A の設計要件（ここが揃わないと A は動かない）

「作者を持たせる」は機能名ではなく、**4 つの回路が閉じている状態**を指す。
現状 4 つのうち閉じているのは 1 つだけ。

| 回路 | 何のためか | 現状 |
|---|---|---|
| **① 返り** 作者に「遊ばれた」が届く | 反応の無い創作は続かない。`playCount` が DB にあるだけでは返りではない | **無い**（数字は他人向けのカードにしか出ない） |
| **② 名前** 遊ぶ側が「誰の世界か」を辿れる | クレジットは表示ではなく**リンク**。作者ページと、その人の他の世界へ行けること | **無い**（`creatorHandle` はただの文字列） |
| **③ 初速** 新作が最初の 10 人に届く | 現在の順位は `playCount + 新着ボーナス`。放置すると必ず**強い世界が強くなるだけ**になり、新しい作者は永久に 0 プレイ | 弱い（新着枠が保証されていない） |
| **④ 転換** 遊ぶ人が作る人になる | UGC で最も難しい転換。ゼロから書かせるのではなく、**遊んだ世界から派生させる**のがいちばん安い | **無い** |

④ が効く理由は原価にもある。1 ワールドの生成原価は約 $0.32 で、これは**プレイ回数で割り算される**。
Status はプレイヤーごとに世界を作るので割り算が起きない。1 万回遊ばれた世界は
1 プレイあたりの世界原価が $0.000032 になる。**作者を持たせることは、コンテンツ供給を
自社の支出から切り離すこと**でもある。§0 で「コストは差別化にならない」と書いたのはアクション単位の話で、
**ワールド単位では複利が効く。**

### 勝ち筋 B: グローバル。日本は最初の一手であって、目的地ではない

Status は**英語のみ**。US / ブラジル / メキシコ / 欧州。
ここで大事なのは「日本が空いている」ことではなく、**こちらのワールドが構造的に多言語であること**。

G9 は作者の言語に関係なく**常に全ロケールを生成する**。実測（replay, `academy`, 作者ロケール ja）：

| | en | ja |
|---|---|---|
| バイブル | 19,357 字 | 8,549 字 |
| キャストカード | 8/8 | 8/8 |
| 雑談プール | 22 | 22 |
| タイトル | New Academy | 放課後・学院 |

つまり**日本語で書かれた世界は、その瞬間から英語で遊べる**。逆も同じ。
Status はこれが原理的にできない（英語しか無い）。

これが本当の意味でのグローバル設計で、言い方はこうなる：

> **世界は言語を超える。ブラジルの誰かが書いた世界を、あなたの言語で遊べる。**

日本を先に開けるのは、①空いている ②ARPU が高い ③**翻訳日本語が即バレる市場なので、
ここで通れば品質が証明される** から。目的は日本市場ではなく、**多言語ワールドという主張の検証**。
検証が済んだら同じ在庫のまま英語圏・ブラジル・欧州に出す。**在庫を作り直さなくていいのが効く。**

さらに運用上の効きも大きい：**日本語のワールドを英語のレビュアーが審査できる**
（バイブルが両ロケールで存在するので）。モデレーション体制を言語ごとに持たなくていい。

> **未検証の前提**: JA の品質は replay（テンプレート合成）でしか確認していない。
> live で日本語が本当に自然かは API キー投入後の最初の検証項目。ここが崩れると勝ち筋 B は消える。

### 勝ち筋 C: 彼らの最大の不満をプロダクトで買う

App Store レビューの最大不満は一貫している：

- 1 アクション = 広告 2 本、30 秒〜2 分
- 年 $350 で 1 日 50 アクション
- **課金しても日次アクションが減った**

これは強欲ではなく**原価の転嫁**。従量課金なのでアクションを配給するしかない。
ここでこちらが同じ原価水準なのは §0 の通りなので、「配給しない」は選べない。
選べるのは**どこで配給を感じさせるか**：

1. **最初のセッションは絶対に広告で止めない。** 初回 90 秒でエネルギー切れに当てない。
   ここで離脱した人は二度と評価しない。
2. **ドラマのビートの途中で広告を挟まない。** 炎上が始まった瞬間に 90 秒の動画広告は、
   体験の破壊であってマネタイズではない。切れ目を設計する。
3. **課金の意味を「回数」から「関係」に移す。** 回数を売るとレビューが「$350 で 50 回」になる。
   Plus の価値を、能動 DM・関係性の設定・世界の作成枠に寄せる（＝すでにそう作ってある）。

## 2. ジェムという第二のマネタイズ軸

Status の課金は全部「行動する権利」を売っている。こちらは **World Studio によって
「作る権利」** が売れる。これは別の財布で、別の心理。

| | 行動を売る | 創作を売る |
|---|---|---|
| 心理 | 消費の継続 | 自己表現・所有 |
| 上限 | 1 日の可処分時間 | 作りたい世界の数 |
| レビューでの見え方 | 「制限されている」 | 「自分の世界が作れた」 |

1 ワールド = 120 ジェム、生成原価は実測**約 $0.32**（Opus 5 の concept/bible を含む 14 呼び出し）。
ジェムパック小 $2.99 = 120 ジェムなので、**粗利は問題ない**。

**問題は人件費のほう。** 公開ワールドは必ず人間が審査する設計にした。1 件 2 分としても、
公開申請が 1 日 1,000 件なら 33 時間/日 = レビュアー 4〜5 人。
**モデレーション費用をユニットエコノミクスに入れていないなら、それは計画ではなく願望。**

### 数字を置くと、設計が破綻していることが分かる

こちらの実装は「公開ワールドは必ず人間が審査する」。そして `docs/moderation.md` と
レビュークレームのリース時間は、**1 件の審査を 20 分**と見積もっている
（バイブル 2 ロケール、キャスト 8 人、通報の本文を読む）。これを金額に直す：

| | 1 ワールドあたり |
|---|---|
| 生成原価（実測、Opus 5 の concept/bible 含む 14 呼び出し） | **$0.32** |
| 審査人件費（20 分 × $15/時） | **$5.00** |
| 同（20 分 × $8/時、オフショア） | $2.67 |
| ジェムパック小の売上（$2.99 = 120 ジェム = 1 ワールド） | **+$2.99** |

**審査が生成の 15 倍高い。** そして**ジェムを満額で買ってもらっても赤字**（$2.99 − $0.32 − $5.00 = **−$2.33**）。
さらに新規アカウントには 120 ジェムを配っている（初日に 1 個作れるように）ので、
**無料の初回ワールドが公開申請されると 1 件あたり約 $5.3 の純損**。

**つまり「全公開ワールドを人間が審査する」は、ワールド販売では絶対に賄えない。**
1 日 200 件の公開申請で人件費 $1,000/日 = $30,000/月。これは MRR $100K の製品の 3 割。

### だから設計をこう変える（未実装、次にやるべき順）

1. **審査対象を減らす。** private / unlisted は審査不要（実装済み）。
   さらに、**公開申請を Plus 特典 + 追加ジェム**にする。棚に並べたい人だけが払う。
2. **信頼度の階段。** 承認実績のある作者は**サンプリング審査**（例: 5 本に 1 本）に落とす。
   審査コストは作者数ではなく**新規作者数**に比例するようになる。ここが一番効く。
3. **自動ゲートに前段を寄せる。** いまの G8 は「ブロックか否か」。
   人間が読む必要のある争点（オリジナル性、13+ の際どさ）を**要約して提示**すれば、
   20 分は 5 分になりうる。$5.00 → $1.25。
4. **通報駆動に寄せる。** 事前審査を薄くし、**公開後の通報閾値**（実装済み）を主防衛にする。
   ただし 13+ で UGC のこの選択は**一度の事故で終わる**種類の賭けなので、
   1〜3 をやり切ってからでないと選べない。

`GET /v1/admin/moderation/metrics` はこの意思決定のために作った。
**「1,000 プレイあたりの通報数」と「人間が取り下げを再承認した率」**が、閾値と体制を実測から
決め直すための 2 つの数字。今の 3 人 / 24 時間はユーザーゼロの製品向けの当て推量にすぎない。

## 3. 数字で置く目標

Status: 200K DL/月、推定 $850K/月、課金率 ~3%。逆算 ARPPU ≈ $15〜20/月相当。

こちらが同じ課金率・ARPPU を仮定すると：

| 目標 MRR | 必要 MAU（課金率 3% / ARPPU $15） |
|---|---|
| $10K | 約 22,000 |
| $100K | 約 220,000 |
| $500K | 約 1,100,000 |

**最初に置くべき数字は MAU ではない。**
初期に見るべきは 3 つだけ：

1. **D1 / D7 リテンション** — Status の 96 分/日 は「1 日目に刺さった人」の数字。
   刺さらなければ何をやっても意味がない。
2. **1 プレイヤーあたりの作成ワールド数と、そのうち他人に遊ばれた率** — 勝ち筋 A が回っているかの唯一の指標。
   「作られた数」ではなく「遊ばれた数」。
3. **1 アクションあたり原価の実測（日次）** — バンディットが品質を落とさずに下げられているか。
   ここは既にダッシュボードがある。

## 4. ローンチの順番 — 日本は「最初の市場」ではなく「最初の検証」

順番を市場で切ると間違える。**回路で切る。**

**Phase 0 — 作者の回路を閉じる（市場を開ける前）**
①返り ②名前 ③初速 ④転換 の 4 つ。ここが閉じていない状態で人を入れると、
入ってきた人は「作れるけど誰にも遊ばれない場所」を見て、二度と作らない。
**UGC の初期は、一度冷えると温め直せない。** ここを先にやる。

**Phase 1 — 日本で招待制ソフトローンチ（多言語ワールドの検証）**
目的は日本市場そのものではなく、**「作者の回路が回るか」と「JA が翻訳臭くないか」の同時検証**。
日本を選ぶのは、翻訳日本語が即バレる市場だから＝**いちばん厳しい審査員が最初に見てくれる**から。
成功条件は 2 つだけ：D7 と、**他人が作った世界のプレイ数**。
（失敗が英語圏に見えない、という副次的な利点もある）

**Phase 2 — 同じ在庫のままグローバル**
Phase 1 で溜まった世界は**すべて英語でも遊べる**（両ロケール生成済み）。
在庫を作り直さずに英語圏・ブラジル・欧州へ。ここで初めて一行の差分が言える：

> **Sims but social media → 誰かが書いた世界で遊ぶ Sims but social media**

**Phase 2 の前に作るべき唯一の大物**：共有が**静止画カード**（SCR-040）しかない。
TikTok / Shorts 起点で伸ばすなら、**ドラマのビートを短い動画として書き出せる**必要がある。
静止画では「この世界おもしろい」が伝わらない。

## 4.5 いま作るべきもの（勝ち筋 A の 4 回路）

| # | 作るもの | どの回路 | なぜ今か |
|---|---|---|---|
| 1 | **作者ページ** `/creator/@handle` — その人の公開ワールド、総プレイ数、フォロー | ② | クレジットが文字列のままだと、作者は「存在」しない |
| 2 | **プレイ数の通知** 「あなたの世界が今日 50 回遊ばれました」 | ① | 反応の無い創作は止まる。通知基盤はすでにある |
| 3 | **新着枠** 発見タブに、順位と無関係な「今日出た世界」の保証枠 | ③ | 現在の `playCount + 新着ボーナス` は放置すると勝者総取りになり、新しい作者が永久に 0 プレイ |
| 4 | **派生（リミックス）** 遊んだ世界から「これの別バージョン」を作る | ④ | 消費者→creator の転換は UGC で最難関。ゼロから書かせるより、既にある premise と genre を種にするほうが桁違いに安い |
| 5 | **言語横断の発見** 発見タブが作者の言語で絞られない | B | 「世界は言語を超える」を主張するなら、UI がそれを裏切ってはいけない |

1〜3 は「回路を閉じる」ための最小セット。4 は増幅器。5 はグローバルの前提。

## 5. 正直なリスク

| リスク | 深刻度 | 手当て |
|---|---|---|
| **流通がゼロ。** プロダクトが同等でも人は来ない | 最大 | プロダクト作業では一切解決しない。Phase 0 を「作るための時間」ではなく「流通を作るための時間」として使う |
| **UGC × 13+ のモデレーション事故** | 存亡 | ゲートは 3 段作った（生成前・公開前・公開後の通報）。だが**一度の事故で終わる**種類のリスクで、技術ではなく体制の問題。`docs/moderation.md` の「レビュアーのローテが無い」は最優先の宿題 |
| **Status が UGC を模倣する** | 高 | $17M と 2 年の先行。3 ヶ月で真似できる。**先行の価値は機能ではなく、その頃までに溜まった作者と作品にしか無い** |
| **JA 品質が実は良くない** | 高 | live 未検証。キー投入後の最初の 1 日で判定する。崩れたら勝ち筋 B は消え、A と C だけで戦うことになる |
| **ASO が不利** | 中 | 「Sims but social media」はカテゴリ名を先取りされている。同じ土俵で名乗らない |
| **課金が「回数」に戻る引力** | 中 | 原価が従量である限り、放っておくと必ず Status と同じ設計になる。Plus の価値を関係性と創作に置き続ける意思決定が要る |

## 6. 一行で

> **同じ原価で同じゲームを作っても勝てない。**
> **勝てるのは、彼らの世界には作者がいなくて、彼らの世界は英語しか話さないから。**
> **どちらもこちら側の実装ではもう可能で、どちらもまだ人間で検証されていない。**
